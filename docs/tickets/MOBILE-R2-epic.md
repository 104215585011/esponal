## 一、先认账:上一轮为什么"做出来不太行"

不是审美问题,是**四条执行架构问题**。都有代码证据:

| # | 问题 | 证据 | 后果 |
|---|---|---|---|
| 1 | **壳没有真正成为"壳"** | `AppShell` 是每页各包一层(`src/app/home/page.tsx` L9、`me/page.tsx`、`review/page.tsx`),其他 10 个页面不包 | 每个页面各自持有一份顶栏/底栏实例,进 tab 就重建一套 chrome → 视觉与位置都对不齐 |
| 2 | **三套导航同时在线上** | `layout.tsx` 仍全局挂 `BottomTabBar`;`MobileTopBar`+`MobileNav`(带抽屉+发音/对话/语法/拆解)仍在 `/talk` 等页;`AppShell` 又自带一套顶栏 | 用户看到的是"拼接"——因为**真的拼了**:旧底栏 + 新底栏 + 抽屉 |
| 3 | **最重要的页面是占位** | `src/app/home/page.tsx` 正文:`首页建设中` | tab 点进去是空壳。壳做得再好,第一屏没内容就判定"不行" |
| 4 | **没有验收基线** | `INFRA-PW`(Playwright 冒烟)停在 `ready_for_qa`;13 张票堆在 `ready_for_qa` | 改完没人能 5 分钟内判断"是不是坏了",于是半成品直接暴露给真机 |

**根因一句话**:把"加个顶栏 + 底栏"当成了 App 壳。真正的手感来自 —— **壳不重建、内容换得干净、动效只有三种**。

**被误判的部分**:`MOBILE-R-000-design.md` 的 IA(5 tab、删抽屉、tab/推入/sheet 三层、四条回退规则)**本身是对的,保留不动**。这次不改 IA,改的是"怎么落地"。

## 二、三条硬原则(违反即重做)

1. **壳只渲染一次**。壳是 `layout`,不是组件包装。tab 之间切换,底栏 DOM 节点不重建、不位移、不闪烁。(判据:DevTools 里给底栏加 `data-shell`,切 tab 时该节点不被移除)
2. **内容先于壳**。任何一屏交付前,必须先有真实内容与真实数据,不允许 `建设中` 占位进真机。
3. **一票一真机**。每期结束必须能独立真机走通,不允许"全做完再看"。

## 三、架构:用路由组做持久壳(这次的关键改动)

> **2026-11-13 落地时的调整(必读)**:原计划是"把页面搬进 `(app)` 路由组"。实际开工时查证:仓库里 **113 个测试文件按相对路径扫描源码**(`src/app/watch/page.tsx` 之类),搬目录会让大批测试因为"文件找不到"变红,收益为 0、噪音极大。**改为不搬文件**:把壳挂到根 `layout.tsx`(App Router 里根 layout 同样跨路由不卸载,满足"壳只渲染一次"),内容让位交给 `body[data-shell]` + `globals.css`。下面的目录树是**目标形态**(等测试改成按模块引用后再迁),当前实现见 `src/app/components/shell/`。

`(app)` 是 Next.js App Router 的**路由组**,括号目录不进 URL。移动/桌面 URL 完全不变,桌面不回退。

```
src/app/(app)/layout.tsx                 ← 持久壳:TabBar + 单播放器 + 安全区 + 滚动记忆
src/app/(app)/(tabs)/home/page.tsx        → /home      tab
src/app/(app)/(tabs)/watch/page.tsx       → /watch     tab(列表)
src/app/(app)/(tabs)/lectura/page.tsx     → /lectura   tab(书架,含我的导入)
src/app/(app)/(tabs)/review/page.tsx      → /review    tab
src/app/(app)/(tabs)/me/page.tsx          → /me        tab
src/app/(app)/(stack)/watch/[videoId]/page.tsx   → /watch/xxx   push(播放页,底栏隐藏)
src/app/(app)/(stack)/lectura/[slug]/page.tsx    → /lectura/xxx push
src/app/(app)/(stack)/import/[id]/page.tsx       → 导入阅读    push
src/app/(app)/(stack)/account/credits/page.tsx   → 积分账户    push
src/app/(app)/(stack)/membership/page.tsx        → 会员        push
```

要点:

- **同级 layout 在子路由间切换不卸载**。`(tabs)` 五个 tab 共用 `(app)/layout.tsx` 的壳实例 → 底栏永不重建,这是"App 感"的地基。
- **推入页放 `(stack)` 组**,由壳按 `pathname` 决定是否渲染 TabBar(或 `(stack)` 自带无底栏 layout)。推入页 = 覆盖,底栏隐藏 = 沉浸。
- **路由表一处声明**:每页 `{ path, level: tab|push|sheet, parentTab }`,`level` 决定有无返回箭头与底栏;`parentTab` 供深链直达时兜底回退。`shell/routes.ts` 已有雏形,直接续用并**修掉 `/watch` 同时是 tab 又是 push 的重复项**(拆成 `/watch` + `/watch/[videoId]`)。
- **单播放器约束放壳层**:一个全局 `AudioContext`/播放引用,任何推入/切 tab 先停他处播放。此前散在各页,是 watch 卡顿的来源之一。
- **滚动记忆**用浏览器原生 + 每 tab 一份偏移量,不用 sessionStorage 每帧补丁(补丁会在返回瞬间跳位,是"破碎感"的来源之一)。
- **壳的存活判定**:壳组件内 `useEffect(() => console.log("shell mounted"), [])` 只允许打印一次(开发态),作为 MOBILE-R2-001 的验收项。

### 为什么不选"单页 state 切 tab"
URL 会丢、深链失效、返回键失效、SEO/分享崩溃。得不偿失。路由组方案能做到视觉上等价,且保住 URL。

## 四、三层导航模型 + 三种过渡(全站只有这三种)

| 层 | 谁 | 顶栏 | 底栏 | 进入/退出 |
|---|---|---|---|---|
| **tab** | 5 个一级页 | logo / 页名 + 搜索 + `+` | 显示,当前态翡翠 | 内容淡入 120–150ms,**无滑动** |
| **push** | 详情:播放页、阅读器、积分、会员、设置、课程日、导入阅读 | 返回箭头 + 标题 | **隐藏** | 右滑入 250ms / 左滑出 250ms |
| **sheet** | 查词卡、导入、选页、倍速 | — | — | 底部上滑 250ms,下拉 / 点遮罩关闭 |

- 动效实现:`view-transition-name` + `::view-transition-*`;不支持时降级为 `transform + opacity`,**不引入动画库**。
- 禁止:弹簧、缩放卡片、tab 横向滑动、逐元素错峰入场以外的花活。列表入场错峰仍按设计语言(0.04/0.12/0.2s)。

## 五、回退模型(四条,治"回退混乱")

1. **tab 页**:无返回箭头。Android 物理返回 → 非首页 tab 回首页;首页 → 退出(可后加双击确认)。
2. **push 页**:箭头 = `router.back()`。**深链直达(无历史)**时回其 `parentTab`(播放页→视频、阅读器→阅读、积分/会员→我的)。
3. **sheet**:物理返回 / 下拉 / 点遮罩 = 关 sheet,**不退出页面**。
4. **流程完成态**:"完成"按钮 = 回流程起点 tab 并**清栈**(不能按返回穿回表单/支付中间页)。

> 现 `useShellBack.ts` 已有前两条骨架,补 3、4 即可。

## 七、流程闭合(五条,每条必须有完成态与去向)

| 流程 | 路径 | 完成态 → 去向 |
|---|---|---|
| 看视频 | 首页/视频 → 播放页 → 点词 sheet → 收藏 | toast「已加入生词本」;返回原 tab,首页"继续学习"卡已更新 |
| 阅读 | 阅读 → 读物 → 查词/收藏 → 退出自动记进度 | 书架卡显示进度 %;读完「已读完 ✅」 |
| 导入 | 任意页 `+` → popover → sheet → 上传条 → 「导入成功」 | 文件 → 推入阅读器;链接 → 直接进播放页 |
| 复习 | 首页待复习 / 复习 tab → 复习流 → 完成页「今日复习完成 ✅ N 词」 | 按钮回首页,待复习卡变 ✅ |
| 积分/会员 | 我的 → 积分账户 → 会员 → 购买 | 成功页 →「返回」清栈回我的,余额即时刷新 |
