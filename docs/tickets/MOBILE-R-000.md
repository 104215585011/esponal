## 要解决的用户原话
> "导航比较乱"、"部分界面回退混乱"、"界面没有整体感,太破碎了,像是一个个拼接起来的"、"很多环节没有闭合"、"没有一个基本的使用框架"

## 交付物(四件,缺一不可)
### 1. App 壳规范(App Shell)
- 一个**全局壳**:底部 tab 栏 + 顶栏 + 页面容器的统一结构;哪些页在壳内(tab 级)、哪些页是壳外的"推入页"(详情级,带返回)。
- **过渡规范**:tab 切换(无动画/淡入)、推入页(右滑入/返回左滑出)、bottom-sheet(上滑)。三种就够,全站统一。
- 安全区、滚动恢复、单 player 约束在壳层怎么处理。

### 2. 导航信息架构(IA)
- **重排所有入口**:现状=底部4tab(视频/阅读/课程/语料库)+顶栏(头像/订阅/搜索)+抽屉(发音/对话/语法/拆解)+导入`+`,全部摊开重新分配:
  - tab 留几个、留哪些(建议含一个"我的/账户"收拢头像抽屉+积分+会员+设置+导入库?由你设计);
  - 二级功能(发音/对话/语法/拆解/导入)从哪进;
  - 搜索/订阅去哪。
- 给出**完整的站点地图**(每个页面:层级、入口、返回去向)。

### 3. 回退规则(Back Model)
- 每一层级的返回行为**一条规则讲清**:tab 页无返回;推入页返回上一层;sheet 下拉关闭;深链(如 /watch?v=)返回到哪。
- 系统返回键(Android/WebView)与界面返回箭头行为一致。

### 4. 流程闭合图(Flow Closure)
- 把核心流程逐条画闭环:**看视频(找→看→查词→收藏→回)/ 阅读 / 导入(传→读)/ 查词→复习 / 积分→会员**。
- 每条流程标明:入口 → 步骤 → **完成态(用户知道"做完了")→ 去向(回哪/下一步建议)**。现状很多流程断头,这是"环节不闭合"的根治。

## 形式
- 总方案文档 `MOBILE-R-000-design.md` + **关键界面 HTML 模型**(壳 + 一个 tab 页 + 一个推入页 + 过渡说明可用文字)。
- 不重设计具体页面视觉(设计语言不变),只定**骨架、导航、流程**。

## 约束
- 白绿设计语言不变;桌面端不回退;单 player;触摸≥44px;按 Capacitor WebView 就绪设计(系统返回键、安全区)。
- 方案要让现有页面**逐步迁入壳**(允许分批),不要求一次性全站切换。
